동적 계획법은 최적화 문제를 여러 개의 부분 문제로 나누고, 각각의 부분 문제를 먼저 해결한 뒤 그 결과를 메모해두는 방식이다. 이후 같은 부분 문제가 다시 필요할 때는 다시 계산하지 않고, 저장해둔 값을 사용한다. 이렇게 부분 문제의 해답을 재사용하면서 전체 문제의 최적해를 구하는 것이 동적 계획법의 핵심이다.

이 방식은 Divide and Conquer와 비슷해 보일 수 있다. 둘 다 큰 문제를 작은 문제로 나누어 해결하기 때문이다. 하지만 차이가 있다. Divide and Conquer에서는 나누어진 부분 문제들이 서로 독립적인 경우가 많다. 예를 들어 각각의 부분 문제를 따로 풀고, 그 결과를 합치면 전체 문제의 답을 얻을 수 있다. 반면 동적 계획법에서는 큰 문제가 작은 문제들의 해답에 의존하고, 같은 부분 문제가 여러 번 반복해서 등장하는 경우가 많다. 그래서 이미 계산한 부분 문제의 결과를 저장해두고 재사용하는 것이 중요하다.

동적 계획법은 설계 방식에 따라 Top-down 방식과 Bottom-up 방식으로 나눌 수 있다. Top-down 방식은 재귀적으로 큰 문제에서 작은 문제로 내려가면서 필요한 값을 계산하고, 이미 계산한 값은 메모해둔다. 이를 memoization이라고도 한다. 반대로 Bottom-up 방식은 가장 작은 문제부터 차례대로 값을 채워 올라가면서 전체 문제의 답을 구한다. 이를 tabulation이라고도 한다.

# Ex Fibonacci
피보나치 수열을 동적 계획법으로 구현해보자. 여기서는 Top-down 방식과 Bottom-up 방식으로 나누어 살펴볼 수 있다.

### Top-down DP
먼저 Top-down DP 방식이다.

![](../images/Pasted%20image%2020260604171721.png)

Top-down 방식에서는 `fib(x)`를 재귀적으로 호출하면서 값을 계산한다. 이때 `dp` 테이블은 처음에 `-1`로 초기화되어 있다. `dp[x]`가 `-1`이 아니라면, 이미 `fib(x)`를 계산한 적이 있다는 뜻이므로 다시 계산하지 않고 `dp[x]` 값을 바로 반환한다.

예를 들어 `fib(5)`를 구한다고 해보자. `fib(5)`를 알기 위해서는 `fib(4)`와 `fib(3)`이 필요하다. 그런데 `fib(4)`를 구하려면 다시 `fib(3)`과 `fib(2)`가 필요하고, 이런 식으로 종료 조건에 도달할 때까지 계속 아래로 내려간다.

이후 가장 작은 값까지 내려간 뒤에는 다시 올라오면서 `fib(2)`, `fib(3)`, `fib(4)`, `fib(5)`의 값을 차례대로 계산한다. 이때 계산된 값들은 `dp` 테이블에 저장된다. 그래서 나중에 같은 값이 다시 필요해지면 재귀 호출을 반복하지 않고, 저장된 값을 바로 사용한다.

----
### Bottom-up DP

Bottom-up 방식은 처음부터 `dp` 테이블을 차례대로 채워나가는 방식이다. Top-down 방식이 큰 문제에서 시작해서 필요한 작은 문제로 내려가는 구조였다면, Bottom-up 방식은 가장 작은 문제부터 계산해서 점점 큰 문제의 답을 만들어간다.

![](../images/Pasted%20image%2020260604172302.png)

피보나치 수열을 예로 들면, 먼저 `dp[0]`과 `dp[1]`처럼 바로 알 수 있는 초기값을 넣어둔다. 그다음 `dp[2]`, `dp[3]`, `dp[4]`처럼 앞에서 계산한 값을 이용해서 순서대로 값을 채운다. 즉, `dp[i] = dp[i-1] + dp[i-2]`라는 관계를 이용해서 `n`번째 값까지 반복문으로 계산하는 것이다.

의사코드를 보면 `n`이 주어졌을 때 필요한 값만 재귀적으로 찾아가는 것이 아니라, `0`부터 `n`까지의 값을 순서대로 전부 계산해둔다. 그래서 나중에 `fib(n)`을 구할 때는 이미 `dp[n]`에 답이 저장되어 있는 상태가 된다.

정리하면 Bottom-up 방식은 작은 문제의 답을 먼저 테이블에 저장하고, 그 값을 이용해서 더 큰 문제의 답을 만들어가는 방식이다. 재귀 호출을 사용하지 않고 반복문으로 구현하는 경우가 많으며, 계산 순서가 명확하다는 장점이 있다.

# Matrix-chaing Multiplication

두 번째 예시는 행렬 곱셈 문제이다. 여러 개의 행렬을 곱할 때는 어떤 순서로 곱하느냐에 따라 전체 연산량이 달라진다. 행렬 곱셈은 결과는 같더라도 괄호를 어디에 치는지에 따라 필요한 계산 횟수가 달라지기 때문이다.

만약 행렬의 개수가 많다면 가능한 한 연산량이 적은 곱셈 순서를 찾고 싶을 것이다. 가장 단순한 방법은 가능한 모든 곱셈 순서를 전부 계산해보는 것이다. 하지만 행렬의 개수가 많아질수록 경우의 수가 급격히 증가하기 때문에 이 방식은 매우 비효율적이다. 그래서 이 문제는 동적 계획법을 활용해서 해결할 수 있다.

행렬 곱셈 순서 문제에서는 두 개의 테이블을 사용한다. 하나는 최소 연산량을 저장하는 `dp` 테이블이고, 다른 하나는 곱셈 순서를 어디서 나누었는지를 저장하는 테이블이다.

`dp[i][j]`에는 i번째 행렬부터 j번째 행렬까지 곱하는 데 필요한 최소 연산량이 저장된다. 예를 들어 `dp[A][B]`라면 A와 B 두 행렬을 곱하는 최소 연산량을 의미한다. `dp[A][C]`라면 A, B, C 세 행렬을 곱하는 최소 연산량을 의미한다.

A, B, C 세 행렬을 곱하는 경우를 생각해보면, 곱셈 순서는 크게 두 가지가 있다. 먼저 A와 B를 곱한 뒤 C를 곱할 수도 있고, 먼저 B와 C를 곱한 뒤 A를 곱할 수도 있다. 이 두 경우의 연산량을 비교해서 더 작은 값을 `dp[A][C]`에 저장한다.

이제 A, B, C, D 네 행렬을 곱하는 경우를 생각해보자. 이때도 가능한 분할 기준을 하나씩 잡아보면 된다. 예를 들어 A와 BCD로 나눌 수도 있고, AB와 CD로 나눌 수도 있고, ABC와 D로 나눌 수도 있다. 중요한 점은 BCD, AB, CD, ABC 같은 부분 문제의 최소 연산량은 앞에서 이미 `dp` 테이블에 계산되어 있다는 것이다. 그래서 다시 모든 경우를 처음부터 계산하지 않고, 저장된 값을 가져와서 사용하면 된다.

즉, 큰 구간의 최소 연산량은 더 작은 구간들의 최소 연산량을 이용해서 계산된다. 이것이 행렬 곱셈 순서 문제에서 DP를 사용할 수 있는 이유이다.

그리고 곱셈 순서를 나누는 기준점을 `k`라고 하면, 어떤 `k`에서 최소 연산량이 나왔는지도 따로 기록해둔다. 이 값을 저장해두면 나중에 실제로 어떤 순서로 행렬을 곱해야 하는지 복원할 수 있다.

#### 초기화
먼저 `n ← length[p] - 1`은 행렬의 개수를 구하는 부분이다. 여기서 `p`는 행렬의 크기 정보를 저장한 배열이다. 예를 들어 행렬 A1의 크기가 `p0 × p1`, A2의 크기가 `p1 × p2`라면, 이런 식으로 행렬들의 차원 정보가 `p` 배열에 들어간다.

그다음 `m[i][i] ← 0`으로 초기화한다. 이것은 행렬 하나만 있을 때는 곱셈을 할 필요가 없기 때문이다. 예를 들어 A 하나만 계산하는 경우에는 연산량이 0이다.

### 행렬 곱 - 변수 설명명

행렬이 `A1, A2, A3, A4, A5` 이렇게 있다고 해보자.

`m[i][j]`는 **Ai부터 Aj까지 곱할 때의 최소 연산량**이다.

예를 들면:

- `m[1][1]` = A1 하나만 있으니까 0  
- `m[1][2]` = A1 A2를 곱하는 최소 연산량  
- `m[2][4]` = A2 A3 A4를 곱하는 최소 연산량  
- `m[1][5]` = A1 A2 A3 A4 A5 전체를 곱하는 최소 연산량

그래서 DP 테이블은 이런 식으로 채워진다.

```text
m[1][1]  m[1][2]  m[1][3]  m[1][4]  m[1][5]
         m[2][2]  m[2][3]  m[2][4]  m[2][5]
                  m[3][3]  m[3][4]  m[3][5]
                           m[4][4]  m[4][5]
                                    m[5][5]
```

아래쪽은 필요 없다. 왜냐하면 `m[3][1]`처럼 A3부터 A1까지 곱한다는 말은 의미가 없기 때문이다.

---

가장 먼저 이해해야 하는 건 `l`이다.

```text
for l ← 2 to n
```

여기서 `l`은 **chain length**, 즉 한 번에 보고 있는 행렬 구간의 길이다.

`l = 2`이면 행렬 2개짜리 구간을 계산한다.

```text
m[1][2], m[2][3], m[3][4], m[4][5]
```

`l = 3`이면 행렬 3개짜리 구간을 계산한다.

```text
m[1][3], m[2][4], m[3][5]
```

`l = 4`이면 행렬 4개짜리 구간을 계산한다.

```text
m[1][4], m[2][5]
```

`l = 5`이면 전체 구간을 계산한다.

```text
m[1][5]
```

즉, `l`은 “몇 개짜리 행렬 묶음을 계산할 건가?”를 뜻한다.

---

그다음 `i`는 **시작 위치**다.

```text
for i ← 1 to n - l + 1
```

여기서 `i`는 현재 구간이 어디서 시작하는지를 뜻한다.

예를 들어 `n = 5`이고 `l = 3`이라고 해보자.  
행렬 5개 중에서 길이 3짜리 구간은 다음 세 개밖에 없다.

```text
A1 A2 A3  → i = 1, j = 3
A2 A3 A4  → i = 2, j = 4
A3 A4 A5  → i = 3, j = 5
```

즉, `i`는 1부터 3까지만 가능하다.

이때 3이 바로 `n - l + 1`이다.

```text
n - l + 1 = 5 - 3 + 1 = 3
```

왜 `+1`이 붙냐면, 시작 위치도 포함해서 세기 때문이다.

길이 3짜리 구간이 `i`에서 시작하면 끝 위치는 `i + 3 - 1`이다.  
끝 위치가 `n`을 넘으면 안 된다.

그래서 조건은:

```text
i + l - 1 ≤ n
```

이걸 정리하면:

```text
i ≤ n - l + 1
```

그래서 반복문이 `i ← 1 to n - l + 1`이 되는 것이다.

---

그다음 `j`는 **끝 위치**다.

```text
j ← i + l - 1
```

이미 `i`는 시작 위치이고, `l`은 구간 길이다.  
그러면 끝 위치 `j`는 자동으로 정해진다.

예를 들어 `i = 2`, `l = 3`이면

```text
j = 2 + 3 - 1 = 4
```

즉, A2부터 A4까지 보는 것이다.

```text
A2 A3 A4
```

여기서 `-1`이 붙는 이유는 시작 행렬 A2도 길이에 포함되기 때문이다.

길이가 3이면 A2, A3, A4니까 끝은 4가 된다.

---

마지막으로 `k`는 **어디서 나눌지**를 뜻한다.

```text
for k ← i to j - 1
```

현재 구간이 `Ai ... Aj`라고 할 때, `k`는 이 구간을 둘로 나누는 기준이다.

예를 들어 `m[1][4]`, 즉 A1 A2 A3 A4를 계산한다고 해보자.

가능한 나누기 기준은 다음과 같다.

```text
k = 1: (A1) (A2 A3 A4)
k = 2: (A1 A2) (A3 A4)
k = 3: (A1 A2 A3) (A4)
```

그래서 `k`는 `i`부터 `j-1`까지만 돈다.  
`k = j`가 되면 오른쪽 부분이 없어지기 때문에 안 된다.

### 행렬곱 - 흐름 설명

이후에는 chain length, 즉 곱할 행렬의 개수를 2개부터 n개까지 늘려가면서 계산한다. `l = 2`이면 행렬 2개짜리 구간을 계산하고, `l = 3`이면 행렬 3개짜리 구간을 계산한다. 이렇게 작은 구간부터 먼저 계산해야 나중에 더 큰 구간을 계산할 때 이미 구해둔 값을 사용할 수 있다.

예를 들어 A, B, C 세 행렬의 최소 연산량을 구하려면 AB를 먼저 계산하는 경우와 BC를 먼저 계산하는 경우를 비교해야 한다. 그런데 이때 AB나 BC의 최소 연산량은 길이가 2인 구간에서 이미 계산되어 있다. 그래서 길이가 3인 구간을 계산할 때는 앞에서 저장해둔 `m[i][k]`, `m[k+1][j]` 값을 그대로 가져와 사용할 수 있다.

여기서 `k`는 곱셈 순서를 어디서 나눌지를 의미한다. i번째 행렬부터 j번째 행렬까지 곱한다고 할 때, `k`를 기준으로 왼쪽 부분은 i부터 k까지, 오른쪽 부분은 k+1부터 j까지가 된다. 그래서 전체 연산량은 `m[i][k] + m[k+1][j] + p[i-1]p[k]p[j]`로 계산된다.

이 식에서 `m[i][k]`는 왼쪽 부분을 곱하는 최소 연산량이고, `m[k+1][j]`는 오른쪽 부분을 곱하는 최소 연산량이다. 마지막의 `p[i-1]p[k]p[j]`는 왼쪽 결과 행렬과 오른쪽 결과 행렬을 최종적으로 한 번 더 곱할 때 필요한 연산량이다.

알고리즘은 가능한 모든 `k`를 하나씩 확인하면서 가장 작은 연산량을 찾는다. 만약 새로 계산한 값 `q`가 현재 저장된 `m[i][j]`보다 작다면, `m[i][j]`를 `q`로 갱신한다. 그리고 그때의 분할 기준 `k`를 `s[i][j]`에 저장한다.

결국 `m` 테이블에는 각 구간별 최소 연산량이 저장되고, `s` 테이블에는 그 최소 연산량을 만들기 위해 어디서 괄호를 나누어야 하는지가 저장된다. 따라서 `m[1][n]`에는 전체 행렬을 곱하는 최소 연산량이 들어가고, `s` 테이블을 이용하면 실제 최적의 곱셈 순서까지 복원할 수 있다.
