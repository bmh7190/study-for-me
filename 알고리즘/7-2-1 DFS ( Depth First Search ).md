DFS는 임의의 꼭짓점에서 시작하여, 현재 꼭짓점과 인접한 neighbor 중 아직 방문하지 않은 꼭짓점을 선택해 연쇄적으로 탐색하는 알고리즘이다. 

이때 현재 꼭짓점에서 더 이상 방문할 수 있는 neighbor가 없으면, 바로 이전에 탐색했던 꼭짓점으로 되돌아가고, 그 꼭짓점에서 다시 방문하지 않은 neighbor가 있는지 확인한다. 이런 과정을 반복하면서 그래프를 깊이 우선으로 탐색한다.

![](../images/Pasted%20image%2020260604130449.png)

A를 시작점으로 DFS를 수행한다고 하자.

A의 인접 정점으로 B, C, F가 있는데, 이 중 B를 먼저 방문한다.
이후 B의 인접 정점을 확인하면 C와 D가 있고, C를 먼저 방문한다.

C에 도착한 뒤 아직 방문하지 않은 인접 정점이 없으므로, 바로 이전 정점인 B로 되돌아간다.
B로 돌아와서 아직 방문하지 않은 다른 인접 정점이 있는지 확인하면 D가 있으므로 D를 방문한다.

D에서도 아직 방문하지 않은 인접 정점이 없으므로 다시 B로 되돌아간다.
이제 B에서도 더 이상 방문할 수 있는 인접 정점이 없으므로 A로 되돌아간다.

처음 A의 인접 정점은 B, C, F였는데, B와 C는 이미 방문된 상태이다.
따라서 아직 방문하지 않은 F를 방문한다.

F의 인접 정점은 C가 있지만, C는 이미 방문된 정점이므로 더 이상 진행하지 않는다.
그래서 다시 A로 되돌아간다.

마지막으로 A에서도 더 이상 방문하지 않은 인접 정점이 없으므로 탐색을 종료한다.

---
DFS를 동작시킨 이후에 모든 edge는 네 종류로 구분한다.

- DFS tree의 edge
- Back edge
- Descendant edge
- Cross edge

![](../images/Pasted%20image%2020260604131301.png)

#### DFS Tree의 edge
DFS를 수행하면 정점들이 처음 발견되는 순서에 따라 DFS tree가 만들어진다. 이때 어떤 정점 `u`에서 아직 방문하지 않은 정점 `v`로 이동하면서 `v`를 처음 발견했다면, 그 간선 `(u, v)`가 **DFS tree edge**가 된다.

즉, DFS tree edge는 DFS가 검사한 모든 간선이 아니라, **새로운 정점을 처음 방문하게 만든 간선**이다.

```
A → B → C
```

이런 식으로 방문했다면 `A → B`, `B → C`가 tree edge가 된다.

주의할 점은, 원래 그래프에 있는 모든 간선이 tree edge가 되는 것은 아니다. 이미 방문한 정점으로 가는 간선은 tree edge가 아니라 다른 종류의 edge로 분류된다.

---
#### Back edge
Back edge는 **후손 정점에서 조상 정점으로 향하는 edge**를 말한다.

예를 들어 DFS tree에서 `A`가 `B`의 조상이고, `B` 쪽에서 다시 `A`로 향하는 간선이 원래 그래프에 존재한다면 그 간선은 back edge가 된다.

여기서 중요한 점은 DFS가 이전 정점으로 되돌아가는 동작 자체가 back edge는 아니라는 것이다. DFS는 탐색이 막히면 함수 호출이나 stack을 통해 이전 정점으로 돌아가지만, 이것은 알고리즘의 backtracking이다.

Back edge는 **그래프 안에 실제로 존재하는 간선**이고, 그 방향이 **후손에서 조상으로 향할 때** 붙는 이름이다.

---
#### Descendant edge
Descendant edge는 보통 **Forward edge**라고도 부른다. 이 edge는 **조상 정점에서 후손 정점으로 향하지만, DFS tree edge는 아닌 간선**이다.

예를 들어 DFS tree가 이렇게 만들어졌다고 하자.

```
A
↓
B
↓
C
```

그런데 원래 그래프에 `A → C`라는 간선도 있었다면, `C`는 이미 `B`를 통해 처음 발견되었기 때문에 `A → C`는 tree edge가 아니다.

하지만 방향은 조상 `A`에서 후손 `C`로 향한다.

```
A → C  : descendant edge / forward edge
```

즉, descendant edge는 조상에서 후손으로 가는 간선이지만, 새로운 정점을 처음 발견하게 만든 간선은 아닌 경우라고 보면 된다.

---
#### Cross edge 
Cross edge는 **조상-후손 관계가 없는 정점들 사이를 연결하는 edge**이다.
즉, DFS tree 기준으로 한쪽이 다른 쪽의 조상도 아니고 후손도 아닌 경우다.

예를 들어 DFS tree 안에서 서로 다른 가지에 있는 정점끼리 연결된 간선이 있다면 cross edge가 된다.

```
A
├─ B
│  └─ C
└─ D
   └─ E
```

여기서 `C`와 `E`는 서로 조상-후손 관계가 아니다. 따라서 이 둘을 연결하는 간선은 cross edge가 된다.

## 의사 코드

DFS의 반복문 방식에서는 stack을 사용한다.

먼저 시작 정점을 stack에 넣는다. 그다음 stack이 비어 있지 않은 동안 정점을 하나 pop한다. pop한 정점의 인접 노드들을 확인하고, 아직 방문하지 않은 인접 노드가 있다면 stack에 넣는다.

인접 노드들을 모두 확인했으면 다시 반복문의 처음으로 돌아간다. stack이 아직 비어 있지 않다면, 다시 stack에서 정점을 하나 pop하고 같은 과정을 반복한다.

이때 stack은 LIFO 구조이므로, 가장 최근에 넣은 정점이 가장 먼저 나온다. 따라서 DFS는 최근에 발견한 정점을 기준으로 다시 그 정점의 인접 노드를 탐색하게 된다. 이 과정이 반복되면서 한 방향으로 계속 깊게 들어가는 탐색이 이루어진다.

![](../images/Pasted%20image%2020260604131923.png)

DFS의 의사 코드는 크게 반복문 방식과 재귀 방식으로 표현할 수 있다.

반복문 방식에서는 stack을 사용한다. 먼저 임의의 시작 정점을 stack에 넣고, stack이 빌 때까지 정점을 하나씩 꺼낸다. 꺼낸 정점을 방문 처리한 뒤, 그 정점의 이웃 정점들을 확인한다. 이때 아직 방문하지 않은 이웃 정점이 있으면 stack에 넣는다.

DFS는 stack 구조를 사용하기 때문에, 최근에 발견한 정점을 먼저 꺼내서 탐색한다. 따라서 한 방향으로 가능한 깊게 들어간 뒤, 더 이상 갈 수 없으면 이전 정점으로 되돌아가는 방식으로 동작한다.

재귀 방식에서는 별도의 stack을 직접 만들지 않아도 된다. 함수 호출 자체가 call stack에 쌓이기 때문이다. 먼저 현재 정점 v를 방문 처리한다. 그다음 v의 이웃 정점들을 하나씩 확인한다. 만약 이웃 정점 u가 아직 방문되지 않았다면 DFS(G, u)를 호출한다. 이 호출이 끝나면 다시 v로 돌아와 남은 이웃 정점을 계속 확인한다.

## 시간 복잡도

DFS에서 시간 복잡도를 생각해보면, adjacency list를 사용할 때 O(n + m)이 된다.

여기서 n은 vertex의 개수이고, m은 edge의 개수이다. DFS는 모든 vertex를 한 번씩 방문하고, 각 vertex의 adjacency list에 들어 있는 edge들을 확인하기 때문에 전체 시간 복잡도는 O(n + m)이 된다.

다만 m의 크기는 그래프의 형태에 따라 달라진다. 일반적인 무방향 단순 그래프에서는 edge 수가 최대 n(n - 1) / 2까지 가능하고, 방향 그래프에서는 최대 n(n - 1)까지 가능하다. 반면 tree에서는 edge 수가 n - 1이므로 DFS의 시간 복잡도는 O(n + n - 1), 즉 O(n)으로 볼 수 있다.

따라서 일반 graph에서는 O(n + m)이라고 표현하는 것이 가장 정확하다.
